# Documentation

Write for the person who has to use it next, in plain words.

## Steps

1. **Find the existing docs** that cover this area and update them rather than adding a new page.
2. **Lead with what the reader can do**, then how, then the details.
3. **Show a real example** for each command or option, with its output when it helps.
4. **Keep reference docs exact:** names, defaults and limits must match the code.
5. **Say what does not work yet**, plainly.
6. **Check links and commands** by running them where you can.

## Style

- Short sentences and full words.
- One idea per paragraph.
- Headings, lists and tables that render well in common Markdown viewers.
